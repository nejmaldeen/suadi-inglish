## ما يعمل حاليًا

- تسلسل الواجهة الكامل: `listening → thinking → speaking → review`.
- وضع عرض مضمون افتراضي بنص ثابت لموقف القهوة.
- وضع مايك اختياري يستخدم `SpeechRecognition` في المتصفح عند توفره، ويرجع إلى العرض المضمون عند التعذر.
- إظهار نص المستخدم، حالة التفكير، الرد، وبطاقة تصحيح نهائية واحدة.
- تصميم الهاتف المتجاوب، بما في ذلك معالجة ارتفاع `100dvh`، safe area، وتمرير محتوى حالة `review` إلى بطاقة التصحيح.
- فصل اتجاه النص: العناوين العربية RTL والجمل الإنجليزية LTR.
- توليد صوت ElevenLabs من الخادم عبر `POST /api/tts` دون كشف المفتاح للمتصفح.
- cache داخل الذاكرة حسب `scriptId` طوال عمر عملية الخادم.
- بدائل صوتية تضمن استمرار العرض.

## مسار الصوت الحالي

النص الصوتي الوحيد المسجل هو `coffee-v1` داخل `lib/voice/scripts.ts`.

تسلسل التشغيل:

1. عند الانتقال إلى `speaking`، ترسل الواجهة `scriptId: coffee-v1` إلى `POST /api/tts`.
2. يرفض المسار أي جسم طلب غير مطابق أو معرّف غير معروف.
3. يعيد المسار نسخة الـMP3 الموجودة في cache إن توفرت.
4. وإلا يقرأ إعدادات ElevenLabs من بيئة الخادم، يطلب الصوت بمهلة 20 ثانية، ثم يعيد `audio/mpeg` ويحفظه في cache الذاكرة.
5. عند فشل API ينتقل التطبيق إلى البدائل بهذا الترتيب:
   - `public/audio/coach-response.mp3` — غير موجود حاليًا.
   - `speechSynthesis` من الجهاز للعربية والإنجليزية.
   - مؤقت احتياطي، ثم الانتقال إلى `review`.

رسائل أخطاء API عامة، ولا تُعاد تفاصيل المزود أو الأسرار إلى العميل.

## ما أُنجز

- واجهة العرض الأساسية واتجاهها البصري المعتمد.
- إصلاح عرض الهاتف وحالة `review` بحيث لا تغطي أدوات التحكم بطاقة التصحيح.
- إزالة مشكلة اتجاه عنوان التفكير «فهمت عليك» عبر تحديد RTL للعربية وLTR للإنجليزية.
- موصل ElevenLabs خادمي يعتمد متغيرات البيئة.
- تثبيت النص الآمن `coffee-v1` بدل استقبال نص حر من العميل.
- cache صوتي داخل الذاكرة.
- ترتيب بدائل التشغيل: API ثم ملف محلي ثم `speechSynthesis` ثم المؤقت.
- اختبارات لمسار البدائل، تحقق API والـcache، HTML المبني، وغياب بيانات ElevenLabs من ملفات العميل و`public`.
- إعداد Git ورفع نقطة الأساس إلى الفرع `main`.
- توثيق التشغيل الآمن في `README.md` و`.env.example`.

## النواقص والحدود الحالية

- لا يوجد مسار STT إنتاجي أو خادمي. الموجود فقط تكامل تجريبي مع التعرف على الكلام في المتصفح.
- لا يوجد LLM أو فهم ديناميكي للنص أو محادثة متعددة الأدوار.
- السيناريو والنص الصوتي ثابتان عند `coffee-v1`.
- ملف `public/audio/coach-response.mp3` غير موجود، لذلك يتجاوزه التطبيق عادةً إلى `speechSynthesis` إذا تعذر ElevenLabs.
- cache داخل ذاكرة العملية فقط؛ يختفي عند إعادة تشغيل الخادم ولا يتشارك بين النسخ.
- لا يوجد تسجيل دخول أو قاعدة بيانات مستخدمين أو دفع أو تقارير أو مكتبة سيناريوهات.
- جودة `speechSynthesis` تعتمد على الأصوات المثبتة في الجهاز والمتصفح.

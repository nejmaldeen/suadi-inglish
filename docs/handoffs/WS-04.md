# تسليم WS-04 — تجربة الجلسة والواجهة

## تعريف المهمة قبل التنفيذ

- الغرفة: `WS-04 — تجربة الجلسة والواجهة`.
- الفرع: `ws/04-session-ui`.
- مسار worktree: `C:\najm\suadi-inglish-worktrees\ws-04-session-ui`.
- الناتج المرئي أو القابل للاختبار: زر الميكروفون الحالي يبدأ تسجيل `MediaRecorder` حقيقيًا، والضغطة التالية توقفه وترسل التسجيل إلى `POST /api/stt`، ثم تعرض `completed.transcript` الخام داخل بطاقة `YOU SAID` قبل متابعة `thinking → speaking → review`.
- اختبار القبول: تنفيذ محاولتين صوتيتين مستقلتين، مع مسح البطاقة الحالية عند بدء المحاولة الجديدة، وظهور transcript مختلف لكل تسجيل، وعدم بدء الدورة بعد خطأ أو قبل `completed`.
- أسباب الفشل المحتملة، بحد أقصى ثلاثة:
  - غموض استمرار التسجيل يجعل المستخدم يتحدث بعد الجملة المطلوبة.
  - انتقال صوت أو transcript من محاولة سابقة إلى المحاولة الجديدة.
  - إكمال الدورة عند رفض الإذن أو غياب الكلام أو فشل الشبكة.
- الفحوص الوقائية المقابلة:
  - عبارة صريحة `جاري التسجيل — اضغط مرة أخرى للإيقاف` مع عداد، وقفل فوري للزر عند الإيقاف وأثناء المعالجة.
  - استدعاء `reset()` قبل كل محاولة جديدة، ومسح transcript، واختبار طلبين بحجمي صوت ونصين مختلفين وتحرير المسارات في كل محاولة.
  - ربط الانتقال إلى `thinking` بحالة `completed` فقط، ورسائل خطأ قابلة لإعادة المحاولة، واختبارات رفض الإذن والصوت الفارغ وانقطاع الشبكة.
- الملفات المتوقعة ضمن ملكية الغرفة:
  - `app/page.tsx`.
  - `tests/session-ui.test.mjs` لاختبارات تكامل تجربة WS-04.
  - `docs/handoffs/WS-04.md`.
- طلبات تعديل ملفات خارج الملكية: لا توجد تعديلات خارج ملكية WS-04. ملاحظة متابعة غير حاجبة إلى WS-02: تقييم دقة الالتقاط/التفريغ لعبارة `order` بعد ظهور `vote` في محاولة بشرية واحدة، من دون أي استبدال صامت أو post-processing داخل WS-04.

## بطاقة الإنجاز

- الحالة الرسمية: `متحقق` داخل WS-04؛ ينتظر مراجعة ودمج WS-00.
- ما تم بناؤه: أزيل `SpeechRecognition` ومسار العرض النصي الوهمي من الإدخال الحقيقي، وربط زر الميكروفون بـ`createPushToTalkController`. الضغطة الأولى تبدأ تسجيلًا مستقلًا، والثانية تستدعي `MediaRecorder.stop()` فورًا، ثم يُقفل الزر أثناء `processing`. تعرض الواجهة الحالات `جاهز / يستمع / يعالج الصوت / اكتمل / حدث خطأ`، وتوضح التسجيل بعداد وعبارة إيقاف صريحة، وتحرر controller عند reset وunmount وحتى إذا اكتمل فتح الميكروفون بعد unmount.
- دليل الإنجاز: أكد المستخدم في اختبار بشري أن الضغط بعد انتهاء الرد يبدأ دورة جديدة وبطاقة `YOU SAID` جديدة بدل إلحاق النص بالبطاقة السابقة. أظهرت الصور transcript خامًا يحفظ الترددات مثل `I would, uh, like to order a flat white, please.` ونتيجة نطق واضحة صحيحة هي `I went to the market yesterday. I would like to order a flat white, please.`. المحاولات ذات `uh` أو `o-order` بقيت خامًا ولم تُصحح. الاختبار الآلي `two push-to-talk attempts upload independent audio and preserve each raw transcript` أثبت طلبين مستقلين بحجمي صوت مختلفين، transcript مختلفًا لكل طلب، وتحرير مساري الميكروفون.
- قيمته للمستخدم: ما يقوله المستخدم فعليًا هو ما يظهر في `YOU SAID`، مع حدود تسجيل مفهومة ومحاولة جديدة نظيفة وقابلية إعادة المحاولة بدل الادعاء بنص ثابت أو إكمال الدورة بعد الفشل.

- ما لم يكتمل: لا يوجد سجل متعدد البطاقات؛ بطاقة `YOU SAID` الحالية تُستبدل عمدًا عند إعادة المحاولة، وهو النطاق المعتمد لهذه المرحلة. لا يوجد تصحيح ديناميكي أو محرك مدرب، ولا تُصحح `vote` إلى `order`. لم يُوصل Gemini أو `/api/coach` أو أي TTS جديد.
